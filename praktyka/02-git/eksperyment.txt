## Передбачення

### 1. У якому розділі `git status` покаже `eksperyment.txt`?
**Передбачення:** одразу у двох розділах — `Changes to be committed`
(версія з «Рядок 2», яку я додав через `add`) і `Changes not staged for commit`
(«Рядок 3», дописаний уже після `add`).

**Git показав:** файл є в обох розділах. Я вгадав, бо індекс зберігає
знімок файлу на момент `git add`, а не сам файл. Усе, що змінилось
після `add`, Git бачить як окрему, ще не додану зміну.

### 2. Що покаже `git diff`, а що `git diff --staged`?
**Передбачення:** `git diff` покаже `+Рядок 3` (різниця між робочою текою
та індексом), а `git diff --staged` покаже `+Рядок 2` (різниця між
індексом і останнім комітом).

**Git показав:** саме так. Я вгадав, бо `git diff` без параметрів показує
те, що ще не додано, а `--staged` — те, що вже піде в коміт.

### 3. Що потрапить у коміт без `add`? Що покаже `git status` після нього?
**Передбачення:** у коміт потрапить лише «Рядок 2», бо `commit` бере
вміст індексу, а не файлу на диску. Після коміту `git status` покаже
`eksperyment.txt` у `Changes not staged for commit` (там лишився «Рядок 3»).

**Git показав:** `git show HEAD` містить лише `+Рядок 2`, а `git status`
показує файл як змінений, але не доданий. Я вгадав, бо коміт фіксує
тільки те, що лежить в індексі. Щоб «Рядок 3» потрапив у коміт,
потрібен ще один `git add`.
